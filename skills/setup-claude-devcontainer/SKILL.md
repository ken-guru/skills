# Setup Claude Code Devcontainer

Adds Claude Code to a devcontainer already generated by the
[setup-devcontainer](../setup-devcontainer/SKILL.md) skill. This skill never
touches `devcontainer.json` or the `Dockerfile` — it only appends its own
marker-keyed content to `post-create.sh`, `post-start.sh` (if skill sync is
opted into), and `README.md`.

## Security contract

This CLI Skill follows the base [CLI Skill security contract](../setup-devcontainer/docs/cli-security-contract.md).
Workspace-derived commands run through the base-owned
`devcontainer-code-runner`; this CLI Skill requests no Capability Seam entry
and no privileged GitHub operation beyond the shared agent-operation contract.

## 1. Detect the base devcontainer

```bash
test -f .devcontainer/devcontainer.json && test -f .devcontainer/post-create.sh && echo ok
```

If either file is missing, **refuse** — tell the user to run
`setup-devcontainer` first, and stop. Do not generate or patch anything.

## 2. Ask this tool's options

- **YOLO alias**: add `claude-yolo` for fast, unattended iteration? Uses
  classifier-based auto permission mode, not `--dangerously-skip-permissions`
  (which breaks `--worktree` — see the template's own comment for why).
- **Automatic skill sync**: sync AI-agent skills into `~/.claude/skills`
  automatically on every container start? Two ready-made suites are
  available — `mattpocock/skills` and `ken-guru/skills` — plus any
  individually named skill in `owner/repo/skill-name` form. Validate each
  individually-named pick live before rendering anything:
  `npx -y skills add <source> --list`; re-ask on a typo or unresolved source
  rather than rendering a broken command. **Only naming a source you trust
  matters here** — this installs and re-syncs that source's skills
  unattended, with no per-skill review step, and an installed skill's
  instructions can influence what the agent does inside the container.

## 3. Patch `post-create.sh`

Append [templates/install-block.sh](templates/install-block.sh) verbatim,
keyed on its own first line as the idempotency marker:

```bash
scripts/patch-if-absent.sh append .devcontainer/post-create.sh "# --- Claude Code ---" templates/install-block.sh
```

(`scripts/patch-if-absent.sh` is the base skill's shared, base-owned
primitive — reference it from `setup-devcontainer/scripts/`, don't copy it.)

If YOLO alias was accepted, also append
[templates/yolo-alias-block.sh](templates/yolo-alias-block.sh), under its own
independent marker so declining now and adding it later never re-triggers
the install:

```bash
scripts/patch-if-absent.sh append .devcontainer/post-create.sh "# --- Claude Code yolo-alias ---" templates/yolo-alias-block.sh
```

## 4. Patch `post-start.sh` (only if skill sync was accepted)

Render [templates/post-start-block.sh](templates/post-start-block.sh) with
`{{SKILLS_SOURCES_COMMANDS}}` substituted to one `npx -y skills add <source>
--skill '*' -a claude-code -y --copy -g` line per whole-suite source (or
`--skill '<name>'` per individual pick), then append it:

```bash
scripts/patch-if-absent.sh append .devcontainer/post-start.sh "# --- Claude Code skill-sync ---" <rendered-block>
```

## 5. Patch `README.md`

Append [templates/readme-bullet.md](templates/readme-bullet.md) to the end of
the file — the base skill positions `## Installed CLI Tools` as `README.md`'s
last section, so a plain append always lands in the right place:

```bash
scripts/patch-if-absent.sh append .devcontainer/README.md "- Claude Code" templates/readme-bullet.md
```

## 6. Verify

Re-run every `patch-if-absent.sh` command from steps 3–5 a second time —
each should produce zero diff. No dedicated verify script exists for this
skill; this re-run *is* the verification.

## 7. Report next steps

Tell the user: rebuild or reopen the container, run `claude` and log in, and
(if YOLO was accepted) `claude-yolo` is now available in every new terminal.
