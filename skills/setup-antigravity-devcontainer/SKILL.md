# Setup Antigravity Devcontainer

Adds Antigravity to a devcontainer already generated by the
[setup-devcontainer](../setup-devcontainer/SKILL.md) skill. This skill never
touches `devcontainer.json` or the `Dockerfile` — it only appends its own
marker-keyed content to `post-create.sh`, `post-start.sh` (if skill sync is
opted into), and `README.md`.

## Security contract

This CLI Skill follows the base [CLI Skill security contract](../setup-devcontainer/docs/cli-security-contract.md).
Workspace-derived commands run through the base-owned
`devcontainer-code-runner`; this CLI Skill uses Docker defaults and requests no
additional Capability Seam or privileged workflow-run operation.

## 1. Detect the base devcontainer

```bash
test -f .devcontainer/devcontainer.json && test -f .devcontainer/post-create.sh && echo ok
```

If either file is missing, **refuse** — tell the user to run
`setup-devcontainer` first, and stop. Do not generate or patch anything.

## 2. Ask this tool's options

- **YOLO alias**: add `agy-yolo` for fast, unattended iteration? Does
  **not** use `--dangerously-skip-permissions --sandbox` — a filed upstream
  bug (`antigravity-cli#36`) makes that combination a no-op sandbox. If
  accepted, this skill's reported next steps still include the curated
  `permissions.allow`-list guidance as a manual, once-per-machine step.
- **Automatic skill sync**: sync AI-agent skills into
  `~/.gemini/antigravity/skills` automatically on every container start?
  Same mechanism as the other CLI skills — two ready-made suites
  (`mattpocock/skills`, `ken-guru/skills`) plus any individually named
  skill, validated live via `npx -y skills add <source> --list` before
  rendering anything.

## 3. Patch `post-create.sh`

Append [templates/install-block.sh](templates/install-block.sh) verbatim:

```bash
scripts/patch-if-absent.sh append .devcontainer/post-create.sh "# --- Antigravity ---" templates/install-block.sh
```

If YOLO alias was accepted, also append
[templates/yolo-alias-block.sh](templates/yolo-alias-block.sh), under its
own independent marker:

```bash
scripts/patch-if-absent.sh append .devcontainer/post-create.sh "# --- Antigravity yolo-alias ---" templates/yolo-alias-block.sh
```

## 4. Patch `post-start.sh` (only if skill sync was accepted)

Render [templates/post-start-block.sh](templates/post-start-block.sh) with
`{{SKILLS_SOURCES_COMMANDS}}` substituted to one `npx -y skills add <source>
--skill '*' -a antigravity -y --copy -g` line per whole-suite source (or
`--skill '<name>'` per individual pick), then append it:

```bash
scripts/patch-if-absent.sh append .devcontainer/post-start.sh "# --- Antigravity skill-sync ---" <rendered-block>
```

## 5. Patch `README.md`

```bash
scripts/patch-if-absent.sh append .devcontainer/README.md "- Antigravity" templates/readme-bullet.md
```

## 6. Verify

Re-run every `patch-if-absent.sh` command from steps 3–5 a second time —
each should produce zero diff. No dedicated verify script exists for this
skill; this re-run *is* the verification.

## 7. Report next steps

Tell the user: rebuild or reopen the container, run `agy` and log in. If
YOLO was accepted, `agy-yolo` is available in every new terminal — **and**
walk them through setting up a curated `permissions.allow` list in
`~/.antigravity/antigravity-cli/settings.json` (starting from `git`, `gh`,
`ls`, `cat`, never `rm`/`curl`/raw `bash -c`/a wildcard) as a manual,
once-per-machine step, since `--dangerously-skip-permissions --sandbox`
doesn't actually sandbox anything for this CLI.
