# Adding the firewall layer later

For a repo that already has a devcontainer (`.devcontainer/devcontainer.json` exists, no
`NET_ADMIN`/`NET_RAW` in its `runArgs`) and now wants the opt-in network egress firewall (ADR-0005:
[../docs/adr/0005-network-egress-firewall-and-network-manifest.md](adr/0005-network-egress-firewall-and-network-manifest.md)).
Mirrors [adding-ssh-later.md](adding-ssh-later.md)'s pattern: this flow only adds the firewall
layer, not the commands or files it depends on that already exist by construction
(`network-manifest.json`, `network-manifest-domains.sh` — both generated by every devcontainer
since ticket #294, firewall opt-in or not).

1. Replace `.devcontainer/Dockerfile` with
   [../templates/Dockerfile.with-firewall](../templates/Dockerfile.with-firewall), copied verbatim
   (no placeholders) — adds the `iptables`/`ipset`/`iproute2`/`dnsutils`/`aggregate` packages and
   the scoped `sudo` rule the firewall scripts need. This is a genuine image change, so it needs
   **Dev Containers: Rebuild Container** later, not just a restart.
2. Copy [../templates/init-firewall.sh](../templates/init-firewall.sh),
   [../templates/refresh-allowlist.sh](../templates/refresh-allowlist.sh), and
   [../templates/firewall-lib.sh](../templates/firewall-lib.sh) to `.devcontainer/`, verbatim (no
   placeholders), chmod +x (`firewall-lib.sh` is sourced, not executed directly, by the other two).
3. If `.devcontainer/allowed-domains.local.txt` doesn't already exist, create it from
   [../templates/allowed-domains.local.txt](../templates/allowed-domains.local.txt), copied
   verbatim — empty except for its explanatory header comment. Never touch it again after this.
4. Add `.devcontainer/allowed-domains.local.txt` to `.gitignore` if it isn't already ignored
   (parallel to how `.devcontainer/.env` is handled in the main flow's step 5).
5. Add the capability grant to `.devcontainer/devcontainer.json`'s `runArgs` (idempotent — safe to
   re-run):
   ```bash
   scripts/patch-json-array-if-absent.sh .devcontainer/devcontainer.json .runArgs templates/firewall-capability-entries.json
   ```
6. Append the firewall invocation to `.devcontainer/post-start.sh` (idempotent):
   ```bash
   scripts/patch-if-absent.sh append .devcontainer/post-start.sh "# --- Network egress firewall ---" templates/post-start-firewall-block.sh
   ```
7. Insert [../templates/README.firewall-block.md](../templates/README.firewall-block.md) into
   `.devcontainer/README.md`, positioned before `## Installed CLI Tools` (which stays the file's
   last section regardless of when the firewall is added), and delete that file's "Network egress
   firewall automation — Not set up here" closing section if present (a devcontainer generated
   before this layer existed at all won't have it — that's fine, `delete-section` is a no-op when
   the heading isn't found):
   ```bash
   scripts/patch-if-absent.sh insert-before .devcontainer/README.md "## Network egress firewall" "## Installed CLI Tools" templates/README.firewall-block.md
   scripts/patch-if-absent.sh delete-section .devcontainer/README.md "## Network egress firewall automation"
   ```
8. Tell the user, in order: rebuild the container now (**Dev Containers: Rebuild Container** — a
   restart alone won't pick up the new Dockerfile or the `runArgs` capability grant); add any of
   this project's own network hosts to `.devcontainer/allowed-domains.local.txt` *before* they're
   needed, since a host that isn't on the Network Manifest, that file, or GitHub's/npm's own
   ranges is unreachable by design once the firewall is up.

Done when `.devcontainer/devcontainer.json` still parses as valid JSON, its `runArgs` contains
`--cap-add=NET_ADMIN` and `--cap-add=NET_RAW` alongside whatever was already there, no `{{...}}`
placeholder remains in any touched file, `## Installed CLI Tools` is still `README.md`'s last
section, and the user has been told to rebuild (not just restart) before the firewall takes
effect.
