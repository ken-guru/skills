# Select the matched production gallery examples

Map: [Document the presentation theme gallery](map.md)
Labels: `wayfinder:grilling`
Status: Closed
Assignee: Codex

## Question

Which exact production fixture slides should represent title, text-plus-image, data or diagram, and section or quotation across Editorial, Signal, and Field Notes, and which one matched comparison should appear in the README so the examples are both visually compelling and honest about shipped behavior?

## Resolution

Use a polished documentation variant of the existing eight-slide production fixture and render it through the same production theme pipeline. Preserve identical slide content and media across Editorial, Signal, and Field Notes so every visible difference comes from the selected Theme Package.

### Dedicated gallery set

Use these exact matched fixture slides:

1. **Slide 1 — Title:** demonstrates overall identity, typography, palette, decoration, composition, and portrait-image treatment.
2. **Slide 4 — Text plus portrait image:** demonstrates the theme-specific composition grammar most clearly; Editorial and Signal place the media to the right in distinct frames while Field Notes uses its tactile media-left composition.
3. **Slide 6 — Data:** produces more revealing theme-specific composition than the diagram fixture, including Editorial's measured grid, Signal's modular metric cards, and Field Notes' organic metric forms.
4. **Slide 8 — Quotation:** gives the clearest comparison of expressive typography, accent use, contrast, attribution, and decorative restraint.

Do not use the landscape slide or diagram slide in the first gallery revision. Their compositions are valid but necessarily more similar across themes, so they add less selection value than the chosen data and quotation slides.

### README comparison

Use **Slide 1 — Title** as the single matched README comparison. It communicates each theme's identity quickly and demonstrates both the typographic system and media treatment. A data slide could incorrectly imply that the themes are primarily data-oriented, while a quotation slide would omit media behavior.

### Rendering source and presentation

- Source every public screenshot from the approved **HTML production render**, the canonical accessible reference output.
- Preserve the complete 16:9 slide; do not crop into details or recompose the slide for documentation.
- Place theme names and explanatory captions in the surrounding Markdown rather than burning labels into screenshot pixels.
- Present themes in stable catalog order: Editorial, Signal, Field Notes.
- State separately that Markdown, HTML, and PDF are generated by default. Documentation does not need duplicate PDF screenshots because the existing parity suite verifies their composition.

### Polished fixture media

The acceptance fixture's current portrait SVG contains visible `LEFT` and `RIGHT` focal-region markers. Keep that diagnostic asset for geometry verification, but do not expose it in public examples.

Create one new portrait-oriented sample image for the documentation fixture with these boundaries:

- Generate it once for the gallery, commit the exact approved raster, and do not regenerate it during routine screenshot refreshes.
- Use the same unchanged image in the title and text-plus-image slides across all three themes.
- Keep it visually neutral with respect to Editorial, Signal, and Field Notes so it demonstrates theme treatment rather than preselecting a matching art direction.
- Provide a protected central subject suitable for the declared portrait orientation, with no essential text, branding, or semantic detail near likely crop boundaries.
- Never reuse the throwaway prototype images as current product evidence.

Place this provenance statement near the gallery comparison:

> The sample artwork was AI-generated for this comparison and is reused unchanged across all themes. The themes control its placement, crop, framing, and treatment—not its underlying artistic style.

The theme gallery therefore remains production evidence: only its sample media differs from the diagnostic capacity fixture, and every documented slide is still generated by the actual Semantic Slide Markup, Theme Package, Marp CSS, and HTML rendering path.
