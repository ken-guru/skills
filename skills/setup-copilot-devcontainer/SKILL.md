# Setup Copilot Devcontainer

Adds GitHub Copilot CLI to a devcontainer already generated by the
[setup-devcontainer](../setup-devcontainer/SKILL.md) skill. This skill never
touches `devcontainer.json` or the `Dockerfile` — it only appends its own
marker-keyed content to `post-create.sh`, `post-start.sh` (if skill sync is
opted into), and `README.md`.

## Security contract

This CLI Skill follows the base [CLI Skill security contract](../setup-devcontainer/docs/cli-security-contract.md).
Workspace-derived commands run through the base-owned
`devcontainer-code-runner`; this CLI Skill uses Docker defaults and requests no
additional Capability Seam or privileged workflow-run operation.

## 1. Detect the base devcontainer

```bash
test -f .devcontainer/devcontainer.json && test -f .devcontainer/post-create.sh && echo ok
```

If either file is missing, **refuse** — tell the user to run
`setup-devcontainer` first, and stop. Do not generate or patch anything.

## 2. Ask this tool's options

- **YOLO alias**: add `copilot-yolo`? This is a manual-invocation reminder
  describing Copilot's current `--allow-all`/`--autopilot` flags, **not** a
  persistent auto-approve alias — GitHub's own docs explicitly warn against
  ever aliasing these flags for every session start.
- **Automatic skill sync**: sync AI-agent skills into `~/.copilot/skills`
  automatically on every container start? Same mechanism as the other CLI
  skills — two ready-made suites (`mattpocock/skills`, `ken-guru/skills`)
  plus any individually named skill, validated live via `npx -y skills add
  <source> --list` before rendering anything.

## 3. Patch `post-create.sh`

Append [templates/install-block.sh](templates/install-block.sh) verbatim —
this includes both the CLI install and the `COPILOT_AUTO_UPDATE=false`
shell-profile export, both mandatory (not opted into):

```bash
scripts/patch-if-absent.sh append .devcontainer/post-create.sh "# --- Copilot ---" templates/install-block.sh
```

If YOLO alias guidance was accepted, also append
[templates/yolo-alias-block.sh](templates/yolo-alias-block.sh), under its
own independent marker:

```bash
scripts/patch-if-absent.sh append .devcontainer/post-create.sh "# --- Copilot yolo-alias ---" templates/yolo-alias-block.sh
```

## 4. Patch `post-start.sh` (only if skill sync was accepted)

Render [templates/post-start-block.sh](templates/post-start-block.sh) with
`{{SKILLS_SOURCES_COMMANDS}}` substituted to one `npx -y skills add <source>
--skill '*' -a github-copilot -y --copy -g` line per whole-suite source (or
`--skill '<name>'` per individual pick), then append it:

```bash
scripts/patch-if-absent.sh append .devcontainer/post-start.sh "# --- Copilot skill-sync ---" <rendered-block>
```

## 5. Patch `README.md`

```bash
scripts/patch-if-absent.sh append .devcontainer/README.md "- Copilot" templates/readme-bullet.md
```

## 6. Verify

Re-run every `patch-if-absent.sh` command from steps 3–5 a second time —
each should produce zero diff. No dedicated verify script exists for this
skill; this re-run *is* the verification.

## 7. Report next steps

Tell the user: rebuild or reopen the container, run `copilot` (auth is
automatic via `GH_TOKEN`). If YOLO guidance was accepted, `copilot-yolo`
prints the current unattended-run flags and their vendor caveat rather than
running anything itself.
