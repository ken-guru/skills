# devcontainer-setup Skill Suite

Six independently invokable Skills for hardening and equipping a devcontainer
that runs an AI coding agent — a Scaffolding Skill for a barebones
devcontainer, plus five Add-on Skills (agentic CLI installs, network
firewall, MCP wiring, CLI lifecycle age-gating, git/SSH auth, DX niceties)
that each retrofit onto a pre-existing Target Devcontainer, not just one this
suite scaffolded itself.

**Unlike Presentation, focused installation is a first-class, supported
path here, not an unsupported side effect.** The whole point of splitting
this suite into Add-on Skills is that you can point one of them at a
devcontainer you built some other way — hand-written, generated by another
tool, inherited from a template — and have it detect what's already there
and add only what it specifically needs. See
[ADR-0001](docs/adr/0001-focused-installation.md) for why this suite
consciously diverges from the Collection's whole-suite-only default.

## Install the complete suite

```bash
npx skills@latest add ken-guru/skills \
  --skill devcontainer-scaffold \
  --skill devcontainer-firewall \
  --skill devcontainer-agentic-clis \
  --skill devcontainer-cli-lifecycle \
  --skill devcontainer-git-auth \
  --skill devcontainer-dx-niceties
```

## Install one Skill

Any member below installs and works on its own — point it at an existing
devcontainer and it retrofits rather than assuming it owns the whole build:

```bash
npx skills@latest add ken-guru/skills --skill devcontainer-firewall
```

## Skills

| Skill | Purpose |
|---|---|
| [devcontainer-scaffold](devcontainer-scaffold/SKILL.md) | Scaffold a barebones devcontainer from scratch: Dockerfile/compose skeletons, non-root user, capability scoping |
| [devcontainer-firewall](devcontainer-firewall/SKILL.md) | Deny-by-default outbound network firewall with a manifest-derived allowlist |
| [devcontainer-agentic-clis](devcontainer-agentic-clis/SKILL.md) | Install agentic coding CLI binaries and wire their MCP servers via stage/verify/atomic-swap |
| [devcontainer-cli-lifecycle](devcontainer-cli-lifecycle/SKILL.md) | Age-gate auto-updated CLI/tool versions against a minimum release age |
| [devcontainer-git-auth](devcontainer-git-auth/SKILL.md) | Deploy key, commit-signing key, and `gh` CLI API authentication |
| [devcontainer-dx-niceties](devcontainer-dx-niceties/SKILL.md) | Host-sleep prevention, config symlink bridging, statusline, database healthchecks |

Each installed member contains every runtime instruction, script, and
supporting file it needs. Members exchange state only by inspecting the
Target Devcontainer's own files (Dockerfile, compose file, devcontainer.json)
— see [CONTEXT.md](CONTEXT.md) for the Add-on Skill / Target Devcontainer /
Retrofit Contract vocabulary this implies, and each member's own SKILL.md for
its exact detection mechanics.

Where one Skill's output feeds another's (devcontainer-agentic-clis adds
vendor-API domains to the allowlist devcontainer-firewall owns), that
dependency is documented on the consuming Skill, not implied by install
order — every member still works if installed and run alone, minus whatever
a Skill it depends on would otherwise have provided.

## External prerequisites

- **Docker** (or a Docker-compatible runtime) and a devcontainer-compliant
  editor or CLI, for all six members.
- **`gh` CLI**, for devcontainer-git-auth and parts of
  devcontainer-agentic-clis and devcontainer-cli-lifecycle that register
  keys or query release metadata via the GitHub API.
- **`jq`**, for devcontainer-firewall's manifest-derived allowlist and
  devcontainer-cli-lifecycle's manifest parsing.

Each member checks only the prerequisite it uses; none require the whole
list to be present.

## Security

This suite's entire premise is that the container is the security boundary
for an agent with real shell and network access. devcontainer-firewall
implements deny-by-default outbound networking; devcontainer-git-auth scopes
credentials narrowly (a repo-scoped deploy key, not an account-wide one); see
each member's own SKILL.md for its specific threat-model reasoning.
